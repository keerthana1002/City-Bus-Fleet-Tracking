## 2. ChatGPT Suggestion Audit Log (Accepted vs. Rejected)

| Suggestion ID | AI Suggestion (ChatGPT) | Decision | Technical Reason |
| :---: | :--- | :---: | :--- |
| **SUG-01** | Use a `@dataclass BusTelemetry` with `gps_signal_active`, `in_tunnel`, and `time_in_tunnel_sec` fields. | **Accepted** | Clean, type-safe telemetry contract that models tunnel GPS signal drops explicitly. |
| **SUG-02** | Maintain per-bus Exponential Moving Average (`_ema_speeds[bus_id]`) with `alpha=0.4`. | **Accepted** | Eliminates jitter from noisy urban GPS updates across 600 buses while retaining last entry speed before a tunnel. |
| **SUG-03** | Store GPS history in an external Redis cluster inside the prototype module. | **Rejected** | Over-engineered for the standalone prototype module; in-memory dictionary (`_ema_speeds`) easily holds 600 float entries (< 50 KB RAM) with zero external setup. |
| **SUG-04** | Deduct `effective_speed * (time_in_tunnel_sec / 3600)` from `distance_to_stop_km` while in tunnel. | **Accepted** | Essential dead-reckoning calculation so ETA decreases steadily as the bus traverses a tunnel. |
| **SUG-05** | Return `None` when `distance_to_stop_km < 0` instead of raising an exception. | **Rejected** | Returning `None` causes downstream `TypeError` crashes; raising `ValueError` enforces fail-fast data validation. |
| **SUG-06** | Clamp minimum effective speed to `5.0 km/h` (`min_speed_kmh`) during heavy traffic. | **Accepted** | Prevents division-by-zero or unrealistic 999-minute ETAs when a bus stops briefly at a signal. |
