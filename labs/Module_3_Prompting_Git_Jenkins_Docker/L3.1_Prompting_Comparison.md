# Lab L3.1 [Basic]: Prompt Engineering Comparison (Role vs. Few-Shot vs. Step-by-Step)

## 1. The Three Prompts Tested on Arrival Time Estimator

### Prompt A — Role Prompting
> *"Act as a Principal Transit Telematics Engineer designing software for a city transport corporation with 600 buses. Write a Python function `estimate_eta` that calculates stop arrival time and handles GPS signal drops inside tunnels."*

### Prompt B — Few-Shot Prompting
> *"Write a Python function `estimate_eta` for a 600-bus fleet following these input/output examples:*  
> *Example 1 (Surface GPS): `dist=6.0 km, speed=30 km/h, gps=True, tunnel=False` -> `mode='LIVE_GPS_EMA', eta_minutes=12.0`*  
> *Example 2 (Tunnel Drop): `prev_speed=36 km/h, dist=4.6 km, gps=False, tunnel=True, t_tunnel=100s` -> `mode='TUNNEL_DEAD_RECKONING', remaining_distance_km=3.6, eta_minutes=6.0`*  
> *Example 3 (Arrived): `dist=0.0 km, gps=True` -> `mode='ARRIVED', eta_minutes=0.0`"*

### Prompt C — Step-by-Step (Chain-of-Thought) Prompting
> *"Build a Python `ArrivalTimeEstimator` class for a 600-bus fleet step-by-step:*  
> *Step 1: Validate that distance, speed, and tunnel time are non-negative.*  
> *Step 2: If distance == 0, return ARRIVED with 0 ETA.*  
> *Step 3: If GPS is active and not in a tunnel, update per-bus EMA speed (`alpha=0.4`) and compute ETA.*  
> *Step 4: If GPS drops in a tunnel, use last known EMA speed and `time_in_tunnel_sec` to subtract distance traveled inside the tunnel, then compute remaining ETA."*
