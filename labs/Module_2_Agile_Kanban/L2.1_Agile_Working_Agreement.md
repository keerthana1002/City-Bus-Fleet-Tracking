# Lab L2.1 [Basic]: One-Page Agile Working Agreement

## Team Charter & Working Agreement (600-Bus Fleet Tracking Team)

### 1. Communication Norms
- **Primary Channels:** `#fleet-600-dev` (daily technical coordination), `#tunnel-eta-alerts` (live simulation & test failures), and GitHub Pull Request threads (code/design discussions).
- **Response SLA:** Blockers affecting the Arrival Time Estimator or 600-bus telemetry ingestion receive a response within **30 minutes** during core hours (09:30–17:30 IST).
- **AI Transparency:** Any code, test, or requirement drafted with **ChatGPT** must be tagged `[AI-Assisted]` in the PR description and peer-reviewed before merge.

### 2. Cadence & Kanban Sync Meetings
- **Daily Kanban Stand-up (15 mins @ 10:00 AM):** Walk the Kanban board right-to-left (`Deployed` -> `Testing` -> `In Progress`), focusing on blocked items and WIP limit breaches rather than individual status recitals.
- **Weekly Replenishment & Risk Review (30 mins, Mondays):** Prioritize backlog items with the Transport Corporation Operations Lead (e.g., tunnel calibration, driver roster rules).
- **Bi-Weekly Retrospective (45 mins, alternate Fridays):** Inspect cycle time, tunnel ETA error margins, and team bottlenecks; commit to 1 actionable workflow improvement.

### 3. Definition of Done (DoD)
A work item for **City Bus Fleet Tracking** is **Done** only when:
1. Code implements scenario targets (supports **600 buses** and **GPS tunnel drop** fallback) and follows PEP 8 standards.
2. Unit and boundary tests pass with **>= 85% coverage** (`unittest` / `pytest`).
3. SonarQube static scan reports **0 Bugs**, **0 Vulnerabilities**, and **Quality Gate = PASSED**.
4. At least **1 peer review approval** is recorded on the GitHub Pull Request (`main` branch protection enforced).
5. Documentation (`README.md` or lab specs) is updated and verified in the Docker container.

### 4. Scope & Change Handling Policy
- **Continuous Pull System:** New operational requests (e.g., new tunnel segment mapping, festival shift swaps) enter the `Backlog` column anytime without disrupting active `In Progress` work.
- **WIP Limit Protection:** Developers pull new cards only when active column WIP is below its cap (`In Development: max 3`, `Testing: max 2`).
- **Urgent Production Hotfixes:** Critical ETA or GPS-ingestion outages bypass the backlog into an `Expedite` swimlane (max 1 item at a time) with immediate pair-debugging.
