# Lab L2.3 [Applied]: Epic Splitting into 5 User Stories with Acceptance Criteria

## Parent Epic
> **EPIC-01: Real-Time Fleet Tracking, Tunnel-Resilient ETA Prediction, and Driver Duty Roster for 600 Buses**  
> *As a Transport Corporation Operations Manager, I want live GPS tracking, accurate tunnel-resilient arrival predictions, and automated shift rosters across all 600 buses so that commuters receive reliable ETAs and buses operate without scheduling conflicts.*

## Split User Stories (5 Stories)

### Story 1 (`US-01` — 5 Story Points): Live GPS Telemetry Ingestion for 600 Buses
- **User Story:** As a Fleet Dispatcher, I want the system to ingest live GPS coordinates and speed from all **600 buses** every 5 seconds so I can monitor the entire fleet in real time.
- **Acceptance Criteria:**
  - **AC1:** System ingests 600 concurrent bus telemetry packets (`bus_id`, `route_id`, `speed`, `distance_to_stop`) within `< 500 ms`.
  - **AC2:** Speed readings are smoothed per bus using Exponential Moving Average (`alpha = 0.4`).
  - **AC3:** Malformed packets (negative speed/distance or empty `bus_id`) are rejected with a `ValueError`.

### Story 2 (`US-02` — 8 Story Points): Tunnel GPS-Dropout Dead-Reckoning Fallback
- **User Story:** As a Commuter, I want my bus arrival time to keep updating accurately even when the bus enters a tunnel and loses GPS signal so I do not miss my bus.
- **Acceptance Criteria:**
  - **AC1:** When `gps_signal_active == False` or `in_tunnel == True`, the estimator switches to `TUNNEL_DEAD_RECKONING` mode automatically.
  - **AC2:** Remaining distance is computed using last known EMA speed multiplied by `time_in_tunnel_sec / 3600`, clamped at `>= 0.0 km`.
  - **AC3:** Upon tunnel exit (`gps_signal_active == True`), mode reverts to `LIVE_GPS_EMA` on the next packet.

### Story 3 (`US-03` — 5 Story Points): Traffic-Adjusted Stop-Level ETA API
- **User Story:** As a Commuter App Client, I want a Python/REST API returning stop-level ETA in both seconds and minutes adjusted for route traffic so I can display arrival countdowns.
- **Acceptance Criteria:**
  - **AC1:** Output payload includes `bus_id`, `mode`, `remaining_distance_km`, `effective_speed_kmh`, `eta_seconds`, and `eta_minutes`.
  - **AC2:** Traffic congestion factor (`traffic_factor > 0`) scales travel speed proportionally without dropping below `5.0 km/h`.
  - **AC3:** When `distance_to_stop_km == 0.0`, response returns `mode = "ARRIVED"` and `eta_seconds = 0`.

### Story 4 (`US-04` — 8 Story Points): Automated 3-Shift Driver Duty Roster for 600 Buses
- **User Story:** As a Depot Roster Manager, I want to generate daily driver duty assignments across Shift-A (06:00–14:00), Shift-B (14:00–22:00), and Night Shift-C (22:00–06:00) for all **600 buses** so every scheduled trip has a driver.
- **Acceptance Criteria:**
  - **AC1:** Every bus (`BUS-001` to `BUS-600`) is scheduled for Shift-A and Shift-B, and 20% of fleet (120 buses) is scheduled for Shift-C (total 1,320 daily assignments).
  - **AC2:** Each assignment maps a unique `driver_id` (`DRV-0001` to `DRV-1320`) with no double-booking in the same shift window.
  - **AC3:** Roster exports cleanly to `data/driver_roster.csv`.

### Story 5 (`US-05` — 5 Story Points): Dispatcher Tunnel Alert & Fleet Health Monitor
- **User Story:** As a Control Room Operator, I want an automated monitor that tracks response latency and highlights buses currently inside tunnels so I can spot delays immediately.
- **Acceptance Criteria:**
  - **AC1:** Monitor logs ETA calculation response time every minute and raises an `ALERT` if latency exceeds the threshold (`15.0 ms`).
  - **AC2:** Summary view displays exact counts of buses in `LIVE_GPS_EMA` vs. `TUNNEL_DEAD_RECKONING` across the 600-bus fleet.
